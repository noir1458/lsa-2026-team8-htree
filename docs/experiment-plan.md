# 실험 계획

작성: 2026-11-18. 성능 측정 전에 정한 비교와 해석 기준이다.

## 가설

1. 작은 인덱스 노드는 선형 탐색으로 비교 분기와 주소 계산을 줄일 수 있다. 원소 수가 늘면 비교 횟수 증가가 불리할 수 있다.
2. 인덱스 탐색이 빨라져도 해시 계산, leaf 검색, inode 처리, 시스템 호출 비용 때문에 파일 조회 전체 차이는 작을 수 있다.
3. 같은 이름을 다시 찾을 때 dentry 캐시가 적중하면 ext4 검색 방식 차이가 사라진다.

어느 가설도 결과로 미리 가정하지 않는다. 이진 탐색을 기준으로 각 방식의 이득과 손해를 모두 기록한다.

## 실험 구분

| 실험 | 조작 | 확인할 것 |
| --- | --- | --- |
| 정확성 | 엔트리 수 1~512, 중복·경계 해시 | 동일한 마지막 hash ≤ target 엔트리 선택 |
| 마이크로벤치마크 | 노드 크기 1,2,4,8,16,32,64,83,128,256,436,442,507,510 | 이진·선형 탐색만 반복했을 때의 ns/search |
| 실제 조회 | indexed 디렉터리 100,1000,10000,100000 파일 | fstatat 전체 시간, 존재·부재 이름별 지연 |
| 캐시 대조 | 디렉터리 열거만 / 이름 조회 예열 | ext4를 실제로 실행했는지 |
| 계측 | 시간 측정과 분리, 동일한 조건 | HTree 노드 크기, 비교 수, leaf 방문 수 |
| 구조 대조 | 인덱스 없는 ext4 디렉터리 | HTree 전체의 역할과 노드 내부 탐색의 차이 |
| 변경 동작 | 생성·삭제·이름 변경·링크 | 각 정책에서 조회 결과 보존 |

## 실행 조건

- 실험 커널 하나에서 binary/linear/hybrid4/hybrid8/hybrid16을 전환한다.
- 별도 원본 B0 커널도 부팅해 실험용 분기와 계측 코드 추가의 영향을 점검한다. 서로 다른 부팅끼리의 차이를 정책 자체의 효과로 단정하지 않는다.
- 같은 round에서는 같은 파일 이름과 검색 순서를 사용한다. 조건 순서는 섞고 다음 round에서 역순으로 실행한다.
- 실제 조회는 기본 10회 반복한다. 존재하는 이름과 없는 이름을 같은 수로 섞는다. 큰 디렉터리는 각각 10000개를 표본으로 조회한다.
- 프로세스를 vCPU 0에 고정한다. 커널 빌드가 끝나고 부팅 후 부하가 가라앉은 다음 측정한다.
- 각 trial 전 sync와 drop_caches=2를 실행한다. 이는 모든 inode/dentry가 반드시 제거됐다는 보장이 아니다. 별도 계측으로 도달 횟수를 확인한다.
- warmdir는 readdir로 디렉터리 블록을 읽고 자식 파일에는 stat하지 않는다. 파일 inode 캐시까지 모두 예열했다는 뜻은 아니다.
- warm은 같은 이름들을 미리 한 번 조회한 뒤 측정한다. 양성·음성 dentry 캐시를 모두 포함한다.
- 탐색 함수 microbench는 파일 조회 전체를 대표하지 않는다. 커널과 같은 선택 규칙을 C로 구현했지만 생성된 기계어와 실행 환경은 다르다.
- microbench는 두 검색 함수만 비교한다. 혼합 정책의 조건 분기를 포함한 결과는 실제 커널 실험에서 확인한다. microbench는 각 크기에서 200만 회씩, 10 round 측정한다.
- VM의 호스트 부하를 통제하지 못한다. trial별 원자료, 중앙값, 범위를 함께 남기며 작은 차이의 순위만으로 주제를 결정하지 않는다.

## 결과에 따른 판단

실제 조회에서 반복 가능한 차이와 그 원인을 설명할 수 있다면 HTree 방향을 확장한다. 함수 내부의 차이만 있고 전체 조회 이득이 불명확하다면 그 경계를 결과로 삼는다. 기존 readahead의 실측 결과는 보존하고, HTree 결과와 구현·설명 가능성을 함께 놓고 발표 주제를 결정한다.
